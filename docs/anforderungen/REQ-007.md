## Beschreibung

Der Code ist über sechs Anforderungen gewachsen und für Anfänger schwer zu lesen: `jointsense/logik.cpp` hat rund 1'550 Zeilen, `jointsense/jointsense.ino` rund 900 Zeilen mit einer sehr langen `loop()` und vielen `#if GUI_MODUS`-Blöcken, `tools/gui/jointsense_live.html` rund 1'160 Zeilen.
Ziel: Der Code wird **leichter lesbar und verständlich**, das Gerät verhält sich aber **genau gleich wie vorher**. Für die Person, die den Sleeve trägt, ändert sich nichts.

Aufräumen heisst zum Beispiel: lange Funktionen in kleinere mit klaren Namen aufteilen, doppelten Code zusammenfassen, toten Code (wird nie ausgeführt) entfernen, Kommentare auf den aktuellen Stand bringen, unklare Namen verbessern. Wie genau, entscheidet der Developer.

**Achtung, Speicher:** Der Programmspeicher (Flash) des Uno ist fast voll. Der Code darf durch das Aufräumen **nicht grösser** werden (siehe AK-5).

## Akzeptanzkriterien

- [ ] AK-1: **Alle bestehenden Tests** (Logik-, Fuzz- und Szenario-Tests von REQ-001 bis REQ-005, Start mit `docs/tests/alle_tests.py`) haben nach dem Aufräumen dasselbe Ergebnis wie vorher. Der Tester hält das Ergebnis **vor** dem Aufräumen als Ausgangslage fest.
- [ ] AK-2: **Schnittstelle unverändert:** In `jointsense/logik.h` bleiben alle öffentlichen Funktionen (Name, Parameter, Rückgabe), alle `struct`s mit allen Feldnamen und Typen und alle `#define`s gleich. Neue öffentliche Funktionen sind nicht erlaubt. Innere (`static`) Hilfsfunktionen in `logik.cpp` dürfen sich frei ändern.
- [ ] AK-3: **Serielle Ausgabe unverändert:** In beiden Modi schickt die Firmware bei gleichen Sensorwerten und Tasten genau dieselben Zeilen (gleicher Text, gleiche Reihenfolge, gleiche Zahlen, gleiches Protokoll aus REQ-006). Auch Baudrate und die Befehle über den Seriellen Monitor bleiben gleich.
- [ ] AK-4: **Beide Modi kompilieren** (`GUI_MODUS 1` und `0`) mit `--warnings all` ohne neue Warnungen. `cppcheck` meldet keine neuen Befunde gegenüber vorher.
- [ ] AK-5: **Speicher nicht grösser:** In beiden Modi Flash ≤ und RAM ≤ der Ausgangslage oben (GUI: ≤ 31'836 / ≤ 1'339 Bytes, Text: ≤ 32'252 / ≤ 1'322 Bytes).
- [ ] AK-6: **Rechenzeit nicht schlechter:** Die gemessene längste Zykluszeit («Zyklus max» bzw. `Z`-Zeile) bleibt unter 15 ms (REQ-002 AK-15) und steigt um höchstens 5 % gegenüber vorher. Geprüft am Board (Wokwi-Kontingent aufgebraucht): Z-Zeilen vorher und nachher vergleichen.
- [ ] AK-7: **Verdrahtung unverändert:** `jointsense/pins.h` bleibt unverändert, im übrigen Code stehen keine Pin-Nummern oder I²C-Adressen als Zahl.
- [ ] AK-8: **GUI gleich:** `tools/gui/jointsense_live.html` liest dieselben Zeilen (G, E, D, P, Z) und zeigt dieselben Werte, Graphen, Farben und Meldungen wie vorher. Keine neuen externen Bibliotheken oder Internet-Adressen.
- [ ] AK-9: **Lesbarkeit:** Keine Funktion in `jointsense/` ist länger als 80 Zeilen (ohne Kommentare und Leerzeilen; Zeilen in `#if GUI_MODUS`-Zweigen zählen alle mit, also beide Zweige zusammen). Kommentare sind auf Deutsch und beschreiben den aktuellen Stand (keine veralteten Kommentare).
